# Configurator Compilation Service Design

## Problem Statement

Currently, user projects generated by `create-app` contain significant pipeline infrastructure (`pipeline-entry.ts`, dual Vite configs, build scripts) that users shouldn't need to understand or maintain. The pipeline is an artifact of our configurator needing a "library" version of user code to render GLB files, not something users should manage.

## Goals

1. **Clean User Experience**: Users should only see their model files and a simple configurator setup
2. **Dynamic Model Discovery**: Adding new model files should automatically work without manual configuration
3. **Maintain V3 Benefits**: Keep static compilation reliability and HMR performance
4. **Hidden Complexity**: All pipeline infrastructure should be managed by the configurator package

## Current Architecture Problems

### User Project Contains Our Infrastructure

```
user-project/
├── main.ts                    # User's model
├── components/                # User's components
├── pipeline-entry.ts          # OUR infrastructure (hardcoded imports)
├── vite.pipeline.config.ts    # OUR build config
├── vite.config.ts             # OUR UI server config
├── scripts/                   # OUR build scripts
└── package.json               # Mixed user/our dependencies
```

### Manual Model Registration

When users add `components/new-model.ts`, they must manually edit `pipeline-entry.ts` to add the import and registration.

## Proposed Solution: Configurator as Compilation Service

### New User Project Structure

```
user-project/
├── main.ts                    # User's model
├── components/                # User's components
│   ├── wheel.ts
│   └── bracket.ts
└── package.json               # Only configurator dev dependency
```

### Configurator Package Exports

The `@manifold-studio/configurator` package will export:

1. **Development CLI**: `manifold-dev` command (handles everything)
2. **Runtime Library**: `startConfigurator()` function (used internally by CLI)
3. **Compilation Service**: Internal pipeline management

## Implementation Architecture

### 1. Development CLI (`manifold-dev`)

Exported by configurator package, handles all development complexity:

```typescript
// @manifold-studio/configurator/bin/manifold-dev.js
export async function startDevelopment(options = {}) {
  const userProjectPath = process.cwd();

  // 1. Discover user's model files
  const modelFiles = await discoverUserModels(userProjectPath);
  console.log(
    "🔍 Discovered models:",
    modelFiles.map((f) => f.id)
  );

  // 2. Generate pipeline entry in our temp directory
  const pipelineEntry = generatePipelineEntry(modelFiles);
  await writeFile("./temp/user-pipeline-entry.ts", pipelineEntry);

  // 3. Start pipeline compiler (our Vite process)
  const pipelineServer = await startPipelineCompiler({
    entry: "./temp/user-pipeline-entry.ts",
    userProjectPath,
    watchPaths: [
      `${userProjectPath}/main.{ts,js}`,
      `${userProjectPath}/components/**/*.{ts,js}`,
    ],
  });

  // 4. Start UI server (serves built-in HTML + configurator)
  const uiServer = await startUIServer({
    userProjectPath,
    pipelinePath: "/temp/pipeline.js",
    isDevelopment: await detectConfiguratorDevelopment(),
  });

  // 5. Set up file watching for model discovery
  setupModelFileWatcher(userProjectPath, () => {
    // Regenerate pipeline entry when models added/removed
    regeneratePipelineEntry();
  });

  console.log("🚀 Manifold Studio development server started");
  console.log(`📱 UI: http://localhost:${uiServer.port}`);
  console.log(`⚙️  Pipeline: http://localhost:${pipelineServer.port}`);
}

async function detectConfiguratorDevelopment(): Promise<boolean> {
  // Check if we're in a workspace with configurator source
  const configuratorSrc = path.resolve("./packages/configurator/src");
  const hasConfiguratorSource = fs.existsSync(configuratorSrc);

  // Check if package.json has configurator as local dependency
  try {
    const packageJson = JSON.parse(fs.readFileSync("./package.json", "utf-8"));
    const hasLocalConfigurator =
      packageJson.devDependencies?.["@manifold-studio/configurator"]?.includes(
        "file:"
      );
    return hasConfiguratorSource || hasLocalConfigurator;
  } catch {
    return hasConfiguratorSource;
  }
}
```

### 2. Built-in HTML Generation and Development Mode

The CLI serves a built-in HTML page that automatically initializes the configurator, eliminating the need for users to create any HTML or JavaScript files:

```typescript
async function startUIServer(options) {
  const { userProjectPath, pipelinePath, isDevelopment } = options;

  const server = await createServer({
    root: userProjectPath,
    plugins: [
      {
        name: "manifold-auto-init",
        configureServer(server) {
          // Serve our built-in HTML for the root route
          server.middlewares.use("/", (req, res, next) => {
            if (req.url === "/" || req.url === "/index.html") {
              res.setHeader("Content-Type", "text/html");
              res.end(generateAutoInitHTML({ pipelinePath, isDevelopment }));
              return;
            }
            next();
          });
        },
      },
    ],
    resolve: isDevelopment
      ? {
          // In development mode, use source imports for HMR
          alias: {
            "@manifold-studio/configurator": path.resolve(
              "./packages/configurator/src"
            ),
            "@manifold-studio/wrapper": path.resolve("./packages/wrapper/src"),
          },
        }
      : undefined,
  });

  return server;
}
```

### 3. Dynamic Pipeline Entry Generation

```typescript
function generatePipelineEntry(modelFiles: ModelFile[]): string {
  const imports = modelFiles
    .map((model, i) => `import * as model${i} from '${model.relativePath}';`)
    .join("\n");

  const definitions = modelFiles
    .map(
      (model, i) => `{
    id: '${model.id}',
    path: '${model.relativePath}',
    name: '${model.name}',
    module: model${i}
  }`
    )
    .join(",\n  ");

  return `// Auto-generated by @manifold-studio/configurator
// DO NOT EDIT - This file is regenerated when model files change

${imports}

const modelDefinitions = [
  ${definitions}
];

// Export pipeline interface
export const pipeline = {
  getAvailableModels() {
    return modelDefinitions.map(def => ({
      id: def.id,
      name: def.name,
      path: def.path
    }));
  },
  
  async generateModel(modelId: string, config: any = {}) {
    const modelDef = modelDefinitions.find(def => def.id === modelId);
    if (!modelDef) {
      throw new Error(\`Model not found: \${modelId}\`);
    }
    
    const result = await modelDef.module.default(config);
    return result;
  },
  
  getModelConfig(modelId: string) {
    const modelDef = modelDefinitions.find(def => def.id === modelId);
    if (!modelDef?.module.config) return {};
    return modelDef.module.config;
  }
};

// Generate manifest data
export const manifestData = {
  models: modelDefinitions.map(def => ({
    id: def.id,
    name: def.name,
    path: def.path,
    config: def.module.config || {}
  })),
  timestamp: ${Date.now()}
};
`;
}
```

### 3. Model Discovery Service

```typescript
interface ModelFile {
  id: string; // 'main', 'wheel', 'bracket'
  name: string; // 'Main', 'Wheel', 'Bracket'
  relativePath: string; // './main.ts', './components/wheel.ts'
  absolutePath: string; // Full file system path
}

async function discoverUserModels(projectPath: string): Promise<ModelFile[]> {
  const patterns = [
    path.join(projectPath, "main.{ts,js}"),
    path.join(projectPath, "components/**/*.{ts,js}"),
  ];

  const files = await glob(patterns);
  const models: ModelFile[] = [];

  for (const file of files) {
    const relativePath = "./" + path.relative(projectPath, file);
    const id = extractModelId(relativePath);
    const name = extractModelName(relativePath);

    // Validate it's actually a model file
    if (await isValidModelFile(file)) {
      models.push({
        id,
        name,
        relativePath,
        absolutePath: file,
      });
    }
  }

  return models.sort((a, b) => {
    // Main model first, then alphabetical
    if (a.id === "main") return -1;
    if (b.id === "main") return 1;
    return a.name.localeCompare(b.name);
  });
}

function extractModelId(filePath: string): string {
  // './main.ts' -> 'main'
  // './components/wheel.ts' -> 'wheel'
  const basename = path.basename(filePath, path.extname(filePath));
  return basename;
}

async function isValidModelFile(filePath: string): Promise<boolean> {
  try {
    const content = await readFile(filePath, "utf-8");
    // Check for export default function or export default
    return /export\s+default\s+(function|async\s+function|\w+)/.test(content);
  } catch {
    return false;
  }
}
```

### 4. File Watching and Hot Reload

```typescript
function setupModelFileWatcher(projectPath: string, onModelChange: () => void) {
  const watcher = chokidar.watch(
    [
      path.join(projectPath, "main.{ts,js}"),
      path.join(projectPath, "components/**/*.{ts,js}"),
    ],
    {
      ignoreInitial: true,
    }
  );

  watcher.on("add", (filePath) => {
    console.log("📁 New model file detected:", filePath);
    onModelChange();
  });

  watcher.on("unlink", (filePath) => {
    console.log("🗑️  Model file removed:", filePath);
    onModelChange();
  });

  return watcher;
}

async function regeneratePipelineEntry() {
  const userProjectPath = process.cwd();
  const modelFiles = await discoverUserModels(userProjectPath);
  const pipelineEntry = generatePipelineEntry(modelFiles);

  await writeFile("./temp/user-pipeline-entry.ts", pipelineEntry);
  console.log(
    "🔄 Pipeline entry regenerated with",
    modelFiles.length,
    "models"
  );
}
```

## User Experience Flow

### 1. Project Creation

```bash
npx @manifold-studio/create-app my-project
cd my-project
```

The `create-app` tool now generates:

- Ultra-minimal user project structure (just model files + package.json)
- Installs `@manifold-studio/configurator` as dev dependency
- Sets up `"dev": "manifold-dev"` script
- No HTML, CSS, or JavaScript files needed

### 2. Development

```bash
npm run dev
```

Behind the scenes:

1. `manifold-dev` CLI starts
2. Detects if running in development mode (configurator development)
3. Discovers user's model files automatically
4. Generates pipeline entry in temp directory
5. Starts dual server setup (pipeline + UI)
6. Serves built-in HTML that auto-initializes configurator
7. Sets up file watching for model changes

### 3. Adding New Models

User creates `components/new-part.ts`:

```typescript
// components/new-part.ts
export default function newPart(config = {}) {
  // User's model code
}

export const config = {
  // Model configuration
};
```

Automatically:

1. File watcher detects new file
2. Pipeline entry regenerated
3. Pipeline recompiled
4. UI updated via HMR
5. New model appears in configurator

## Migration Strategy

### Phase 1: Implement Compilation Service

- Build the CLI and compilation service in configurator package
- Create model discovery and pipeline generation logic
- Test with existing V3 development setup

### Phase 2: Update create-app Templates

- Remove pipeline infrastructure from templates
- Add configurator as dev dependency
- Update package.json scripts to use `manifold-dev`

### Phase 3: Backward Compatibility

- Support both old and new project structures during transition
- Provide migration guide for existing projects
- Deprecate old approach gradually

## Development Experience Preservation

### Configurator Development Mode

When developing the configurator itself, the CLI automatically detects the development context and preserves our fast HMR workflow:

**Detection Logic:**

- Checks for `./packages/configurator/src` directory
- Checks for local file dependencies in package.json
- Automatically switches to development mode

**Development Mode Features:**

- Uses source imports (`/@fs/packages/configurator/src/index.ts`) instead of package imports
- Enables Vite aliases for direct source access
- Watches configurator source files for changes
- Maintains same HMR performance as current workflow

**Example Development Workflow:**

```bash
# In our monorepo
cd test-v3-development
npm run dev  # CLI detects development mode automatically

# Make changes to packages/configurator/src/components/ModelViewer.ts
# Changes trigger HMR immediately, just like current workflow
```

This ensures we don't sacrifice our development productivity while giving users the cleanest possible experience.
